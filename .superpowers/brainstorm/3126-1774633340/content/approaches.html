3 Approcci Architetturali

Scegli l'approccio che preferisci — o di' cosa vuoi combinare

A

Python Monolith + React + PyQt6 Overlay

Un solo processo Python gestisce tutto: audio monitoring, cattura, trascrizione, AI, API REST, storage. React (Vite) servito da FastAPI. Overlay = finestra PyQt6 always-on-top in thread separato.

Pro

  • Meno parti mobili
  • Deploy semplice (un solo processo da avviare)
  • Overlay nativo Windows, look professionale

Contro

  • PyQt6 aggiunge dipendenza pesante
  • Un crash blocca tutto

Stack: Python · FastAPI · PyQt6 · SQLite · React/Vite

B

Python Backend + React + Mini Electron Overlay ⭐ Consigliato

Python FastAPI gestisce audio, trascrizione, AI, storage. React standalone per il frontend. Mini processo Electron dedicato solo all'overlay: finestra trasparente always-on-top, riceve aggiornamenti via WebSocket dal backend.

Pro

  • Overlay bellissimo e flessibile (HTML/CSS)
  • Se crasha l'overlay, il backend continua
  • Ogni componente è indipendente e riavviabile
  • Electron overlay è ~10MB, leggero

Contro

  • 3 processi da gestire all'avvio
  • Node.js + Python come dipendenze

Stack: Python · FastAPI · SQLite · React/Vite · Electron (solo overlay) · WebSocket

C

Electron Full Shell + Python Backend

Electron è il contenitore principale: lancia il backend Python come subprocess, gestisce l'overlay (BrowserWindow always-on-top), e ospita il frontend React. Pacchettizzabile come installer Windows (.exe).

Pro

  • Un solo installer Windows
  • Esperienza app desktop completa (tray, notifiche native)
  • Sistema tray integrato

Contro

  • Electron è pesante (~150MB baseline)
  • Gestione del ciclo di vita Python subprocess è complessa
  • Overkill se non si ha bisogno di distribuzione

Stack: Electron · Python · FastAPI · SQLite · React/Vite
